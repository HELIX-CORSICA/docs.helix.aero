These three tools read and write files. They do the same work as the **Import** menu and the **Export** window of the application. See [Import data](/flight-planner/import-export/importer) and [Export the flight plan](/flight-planner/import-export/exporter).

| Tool | Role |
|---|---|
| [`kml_import`](#kml_import) | Imports polygons from files as zones. |
| [`obstructions_import`](#obstructions_import) | Imports obstructions from a file. |
| [`mission_export`](#mission_export) | Writes the mission to a KMZ, KML or .helix file. |

<Warning>
The paths you give are **read and written by the application**, not by `helix-cli`. Always give absolute paths, on a disk the application can reach. See [Arguments](/cli/utilisation/arguments#file-paths).
</Warning>

## `kml_import`

Imports the polygons of KML, KMZ, GeoJSON or GPX files as zones of the active flight. The name of each polygon in the file (the name of the Placemark in a KML) becomes the name of the zone. If the mission has no flight yet, a flight is created.

| Argument | Type | Required | Description |
|---|---|---|---|
| `paths` | list of texts | Yes | The paths of the files. At least 1. Repeat the option once per file. |

```sh
helix-cli kml_import --paths "C:/Data/zone-nord.kml"
helix-cli kml_import --paths "C:/Data/zone-nord.kml" --paths "C:/Data/zone-sud.kmz"
```

**Result:**

| Field | Content |
|---|---|
| `elementIds` | The identifiers of the zones that were created. |
| `skipped` | Number of entities that were ignored: those that are not valid polygons. |
| `files` | Number of files read. |

Things to know:

- **Several files at once require the Pro plan.** Without it, the command ends with `LICENSE_REQUIRED: plusieurs fichiers : plan Pro requis (import.multi_kml)` and exit code 4. With a single file, there is no restriction of this kind.
- The zones of all the files arrive together, in one step of the history: a single [`history`](/cli/reference/elements-et-geometrie#history) `--action undo` cancels the whole import.
- An unreadable file stops the command with `INVALID_ARGS`, and the message starts with the path of the file. No zone is created in that case.
- If no valid polygon is found, the command gives `INVALID_ARGS` with the number of ignored entities.

## `obstructions_import`

Imports the obstructions of a KML, KMZ or GeoJSON file into the active flight.

| Argument | Type | Required | Description |
|---|---|---|---|
| `path` | text | Yes | The path of the file. |

```sh
helix-cli obstructions_import --path "C:/Data/obstacles.geojson"
```

**Result:** `obstructionIds`, the identifiers of the obstructions that were added. If nothing could be imported, the command ends with `INVALID_ARGS`, with the reason given by the application when there is one.

To add a single obstruction from its coordinates, use [`obstruction_add`](/cli/reference/elements-et-geometrie#obstruction_add).

## `mission_export`

Writes the mission to a file.

| Argument | Type | Required | Description |
|---|---|---|---|
| `format` | `kmz`, `kml` or `helix` | Yes | The file format. |
| `path` | text | Yes | The path of the file to write. |
| `flightIds` | list of texts | No | The flights to export. By default, the active flight. |

The formats:

| `format` | File | Notes |
|---|---|---|
| `kmz` | DJI wayline (KMZ WPML) | For computed flights. |
| `kml` | Flight lines | |
| `helix` | `.helix` mission file | Writes the whole mission. `flightIds` has no effect. |

```sh
helix-cli mission_export --format kmz --path "C:/Missions/corte-lot3.kmz"
helix-cli mission_export --format kml --path "C:/Missions/corte-lot3.kml" --flightIds <flight1> --flightIds <flight2>
```

**Result:** `path`, `format` and `flightIds`, as they were used. The command answers **once the file is written**.

Things to know:

- Compute the plan of the flights before a `kmz` export (see [`plan_compute`](/cli/reference/planification#plan_compute)).
- Each format follows the license rules of the interface. A format your license does not allow gives `LICENSE_REQUIRED` and exit code 4.
- If the export is refused or fails, the command ends with the real reason, for example a missing terrain or a missing aircraft. The same checks as in the **Export** window apply.
- With no flight to export, the command gives `NOT_FOUND` (`aucun vol à exporter`). An empty `path` gives `INVALID_ARGS`.
